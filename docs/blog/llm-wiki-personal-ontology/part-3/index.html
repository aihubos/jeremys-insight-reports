내 Obsidian Vault를 AI가 읽을 수 있게 바꾸는 법

폴더 정리가 아니라 지식 구조 만들기

Obsidian을 오래 쓰다 보면 파일은 계속 쌓인다.

문제는 파일이 많아질수록, 나도 못 찾고 AI도 못 읽는 구조가 되기 쉽다는 점이다.

그래서 나는 Vault 전체를 한 번에 정리하려고 하지 않았다.

AI가 읽을 수 있는 길부터 만들기 시작했다.

Obsidian Vault가 AI용 지식 구조로 펼쳐지는 장면

1. Inbox는 입구다

내 Vault에서 Inbox는 빠른 입력 공간이다.

대화, 링크, 보고서, 블로그 아이디어, 나중에 정리할 생각이 들어온다.

Inbox의 역할은 완벽한 정리가 아니다.

일단 놓치지 않는 것이다.

정리는 그 다음이다.

2. LLM Wiki는 정제 레이어다

반복해서 쓸 만한 내용은 LLM Wiki로 보낸다.

여기서 raw 자료는 원본 또는 출처 역할을 하고, pages는 개념화된 지식 페이지가 된다.

내가 쓰는 기본 구조는 이렇다.

raw

pages index.md log.md schema 질문 인덱스</code></pre>


이 구조가 생기면 AI가 단순히 파일을 읽는 게 아니라, 어디서 시작해야 하는지 알 수 있다.


raw pages index log schema가 층으로 쌓인 구조


3. index는 사람을 위한 지도다


index.md는 사람이 보는 목차다.


어떤 지식 지도가 있는지, 어떤 페이지가 핵심인지, 어디부터 읽어야 하는지 보여준다.


AI에게도 중요하지만, 사람인 나에게도 중요하다.


내가 못 읽는 구조는 오래 못 간다.


4. 질문 인덱스는 AI와 대화하기 위한 지도다


문서 제목을 정확히 아는 경우는 생각보다 적다.


보통은 이렇게 묻는다.


  • AI 자동화는 어떻게 설계하지?
  • 내 지식을 자산화하려면 어떤 흐름이 필요하지?
  • 이 주제로 블로그를 쓰려면 어디부터 봐야 하지?


그래서 질문 인덱스가 필요하다.


문서 중심이 아니라 질문 중심으로 탐색하게 해준다.


5. 파일 우선 원칙이 중요하다


나는 도구보다 파일이 중요하다고 본다.


앱은 바뀐다. 서비스는 사라질 수 있다. 하지만 Markdown 파일은 남는다.


AI가 읽고, 내가 고치고, 다른 도구로 옮길 수 있어야 한다.


Markdown 파일을 중심으로 여러 도구가 연결되는 장면


마무리


AI가 잘 쓰는 지식은 결국 사람이 봐도 구조가 명확한 지식이다.


그래서 Obsidian을 AI용으로 바꾼다는 건, 화려한 플러그인을 많이 깐다는 뜻이 아니다.


입구와 정제소와 지도와 기록을 만드는 일이다.
