LLM Wiki는 RAG와 뭐가 다를까

찾기와 다시 쓰기의 차이

LLM Wiki를 이야기하면 자연스럽게 RAG가 떠오른다.

둘 다 많은 자료에서 답을 찾기 위한 방식이다.

하지만 내가 써보며 느낀 핵심 차이는 명확했다.

RAG는 찾기에 강하고, LLM Wiki는 다시 쓰기에 강하다.

RAG와 LLM Wiki의 차이를 보여주는 비교 이미지

1. RAG는 빠르게 찾아준다

RAG는 원본 문서를 조각으로 나누고, 임베딩하고, 질문이 들어오면 관련 조각을 찾아 LLM에 넣는 방식이다.

빠르다. 대량 문서에 좋다. 검색 시스템으로는 강하다.

특히 회사 문서, 제품 매뉴얼, 법률 자료처럼 원본을 빠르게 검색해야 할 때 유용하다.

하지만 개인 지식관리에서는 조금 다른 문제가 생긴다.

찾은 조각이 내 생각의 구조가 되지는 않는다.

2. LLM Wiki는 읽고 고칠 수 있다

LLM Wiki는 원본을 검색하는 데서 끝나지 않는다.

원본을 읽고, 요약하고, 개념 페이지로 바꾸고, 관련 문서와 연결한다.

무엇보다 결과물이 Markdown이다.

내가 읽을 수 있고, 수정할 수 있고, 다른 글로 재사용할 수 있다.

데이터 조각이 Markdown 지식 페이지로 정리되는 장면

3. 개인 지식에는 편집 가능성이 중요하다

개인 지식은 고정된 문서가 아니다.

오늘의 생각이 내일 바뀐다. 어제의 메모가 다음 달 블로그 주제가 된다. 하나의 대화가 제품 아이디어로 이어진다.

그래서 검색만 잘되는 것보다, 계속 고치고 다시 연결할 수 있는 구조가 중요하다.

LLM Wiki는 이 점에서 나에게 잘 맞았다.

4. 둘은 경쟁이 아니라 역할이 다르다

나는 RAG가 나쁘다고 생각하지 않는다.

오히려 둘은 보완 관계에 가깝다.

RAG / 검색 도구

→ 빠른 원본 탐색


LLM Wiki → 오래 쓸 지식으로 정리</code></pre>


검색은 입구고, 위키는 축적이다.


검색 결과가 편집 가능한 위키 페이지로 합쳐지는 장면


5. 내가 선택한 기준


내 기준은 단순했다.


나중에 다시 볼 수 있는가. 내가 직접 고칠 수 있는가. 블로그와 보고서로 바꿀 수 있는가. AI가 다음에도 읽을 수 있는가.


이 질문에 더 잘 맞는 쪽이 LLM Wiki였다.


마무리


RAG가 검색 엔진이라면, LLM Wiki는 편집 가능한 지식 지도다.


내 목적은 단순 검색이 아니었다.


내 생각이 다시 연결되고, 다음 글과 다음 판단에 쓰이는 구조를 만드는 것이었다.
