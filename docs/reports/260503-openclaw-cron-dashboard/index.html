리스크/비판적 관점

  • 21:00 집중도가 높음: 굿나잇, 꿈 일기, 블로그 초안, 업데이트 알림, Graphify가 동시에 실행되어 사용자 알림이 몰릴 수 있음
  • 브리핑 중복 가능성: 모닝/미국주식/점심/특갤/굿나잇이 모두 알림형이라, 정보량이 많을 날에는 피로도가 커질 수 있음
  • LLM-Wiki 자동화는 강하지만 복잡함: import → ingest → graph → lint → weekly update가 잘 나뉘어 있으나 장애 시 원인 추적이 어려울 수 있음
  • 비활성 작업 방치: 실패 이력이 있는 watcher, 과거 알림, 종료된 토론모드가 남아 있어 운영 화면을 흐림
  • Memory embedding 오류가 남아 있음: memory_search가 Gemini API Key 오류로 비활성이라 장기 기억 기반 자동화 품질에 영향 가능

Obsidian 볼트 고도화 제안

  • 000_Inbox는 임시 수집함으로만 유지: ingest 완료 문서는 ingest_status 표시 후 Areas/Projects/Resources로 이동
  • 010_Todo 루트 폴더는 금지: ToDo는 000_Inbox/To Do List.md 단일 표로 운영하고, 과거 CSV는 000_Inbox/todo-imports/에 보관
  • Home 영역 신설은 좋은 방향: 200_Areas/230_Home/동탄2 C-14 입주/처럼 장기 생활 영역은 Areas에 둔다
  • LLM-Wiki는 raw/pages/index/log 4계층 유지: 원본 보존, 지식화, 인덱스, 변경 기록이 분리돼 있어 확장성 좋음
  • 대시보드형 MOC 강화: 블로그, 집, 투자, 자동화처럼 반복해서 보는 영역은 00_대시보드.md를 첫 문서로 둔다
